# Klyp timeline editor design

## Intent

Make editing a saved streamer clip feel direct and visual, as in the two approved Klyp mockups. A creator should see the vertical result, hear and seek through the real clip, cut out a weak section, correct captions, adjust the hook, undo a mistake, save, and export exactly those choices. The editor must work with the creator's footage rather than the illustrative footage in the images.

The primary visual references are [the detailed editor mockup](../assets/klyp-editor-secondary-reference.png) and [the earlier composition mockup](../assets/capcut-style-editor-reference.png). Match their dark surfaces, mint selection/playhead, large central preview, right inspector, and bottom multi-track timeline. The detailed mockup leads where the two differ.

## Approach and release boundary

We considered expanding the existing small Details panel, adopting a generic editor library, and building a dedicated Klyp editor page on the current saved-draft and export pipeline. The dedicated page best fits the mockups and preserves Klyp's existing clip, layout, billing, and archive logic. The user chose a **working core editor first**, and chose **real video/audio cuts** for Split and Delete.

The first release includes the transcript, vertical preview, inspector, and timeline. It excludes imported photos/videos, separate music tracks, templates, brand kits, transitions, rearranging source segments, social posting, and scheduling. Controls for those later features must not appear as working buttons or pretend to save. Do not change Free/Pro pricing or format gates in this release. A free user can view the clip and the Pro editing gate remains in force.

## Creator flow

1. From a saved clip, open **Edit** into a dedicated wide-screen page. The existing quick preview remains available. The editor loads the owned clip and its saved draft, warns if a newer or invalid draft cannot be read, and never exposes another user's clip.
2. The center preview is playable, 9:16 by default, and uses the saved account or clip layout. It shows the selected hook and active caption over the same moment that the playhead indicates. If preview footage cannot load, show a retryable error and keep editing metadata possible.
3. A timestamped transcript on the left highlights the current speech and can seek the player. Search narrows or finds transcript lines without changing the clip. Old clips without word timestamps show an honest empty state; trim, hook, title, and video editing still work.
4. The bottom timeline has a time ruler, real frame thumbnails, a real audio waveform when audio exists, separate video, captions, and hook lanes, a draggable/clickable playhead, and zoom. Track positions are proportional to **edited output time**, not arbitrary widths. Play/pause and previous/next cue stay synchronized with the preview. Keyboard Space toggles playback except while typing.
5. Drag video trim handles or set precise Start/End values for the **selected segment**. The inspector uses original source timestamps; the bottom ruler uses edited output time. **Split** divides the selected video segment at the playhead; **Delete** removes the selected segment and closes the gap in video and audio. Only one video or caption item is selected at a time, so Delete has an unambiguous target. The remaining segments stay in source order within the original saved clip. At least one playable segment must remain. The preview skips deleted source spans; export concatenates the kept spans and their source audio without inserted silence. Time labels and caption positions update after cuts. No Spark charge occurs for editing or previewing.
6. Click a caption block to edit its text and timing in the right inspector; split at the playhead only when it falls inside the selected cue, keeping the text on both halves initially, or delete the selected caption without cutting video. Keep auto-generated word timing as the initial cue source. Caption edits have stable IDs and source-time anchors so later video cuts remap them; a cue crossing a removed span becomes separate visible fragments, and a fully removed cue disappears. The caption Style panel uses the existing BOLD/CLEAN/KLYP presets and adds the mockup's limited color and vertical-position choices. Hook suggestions, existing five hook styles, and first-three-seconds behavior remain available. Caption and hook overlays must agree with export in timing, words, placement, and selected style.
7. Undo/Redo covers unsaved video cuts, trim, captions, hook, and style changes. **Save** persists one versioned draft on the clip. Status says **Saved to Klyp** only after server confirmation, never merely after local state changes. Export uses the current visible draft, preserves the existing watermark, plan, and Sparks rules, and reports failures without discarding edits. Closing or navigating with unsaved changes warns the creator.

## Data and rendering contract

- Extend the existing `clips.edit_draft` JSON contract compatibly. Old saved version-1 drafts retain their trim/text/layout choices. A new versioned draft records ordered kept source segments, caption cue overrides, and caption appearance. Validate finite times, bounds within the original clip, non-overlap, minimum useful segment/cue duration, reasonable item/text limits, and total edited duration at most 180 seconds on both client and server.
- Define one pure time mapping between edited output seconds and original source seconds. Playback, transcript highlight, thumbnails, waveform, caption lane, hook position, and FFmpeg export consume this mapping. Splitting a segment does not itself change output; deleting it does. Undo restores the previous complete draft. The video lane uses real frame thumbnails inside each kept segment; dialogue text belongs on the caption lane.
- The processing service cuts and concatenates each kept source span in source order, including audio. It must work from an archived master or the original VOD segment, use absolute VOD times correctly, and keep caption/hook timing aligned after removed spans. The existing single-range path remains for older drafts and other callers.
- Caption overrides are explicit source-time cues with stable IDs; the original word transcript remains available for transcript/search and old exports. The browser preview and ASS/FFmpeg export use the same resolved cue list and appearance settings. Limit styles to validated hex colors and shared Top/Center/Bottom positions. Test representative rendered frames and audio duration against the preview model; slight browser/server font rasterization differences are acceptable.
- Thumbnails and waveform represent the user's real preview media. If generation fails or the clip is silent, show an honest unavailable/flat state rather than invented imagery. The editor should remain responsive while media loads.
- The feature builds on saved-editor PR #9 and vertical-layout PR #12. The SQL migrations for those PRs remain hand-applied through the Supabase SQL editor. If this work needs additional SQL, provide a separate numbered migration and never run it by CLI.

## Release and verification

Work on a new branch and PR stacked on PR #12; do not push to `main`. The app and processing service both need the code before real multi-cut exports can work. Test validation and edited/source time mapping, split/delete/undo, legacy drafts, archived and source export, caption timing, audio continuity, preview/export parity, ownership, and failure states. Verify TypeScript and the deploy build. Keep the PR draft until a browser test on an owned clip and a rendered MP4 comparison are done. A live test must not analyze a VOD or spend Sparks without the user's agreement.
